# 视频评测集:检查点标注指引

你要做两件事,加起来约 4~5 小时:

1. **标 ~100 个检查点帧**(每段 6~18 帧)—— 在 X-AnyLabeling 里校正预标注
2. **记 ~40 个"新牌出现事件"的时间戳** —— 用播放器定位,填进 `events_gt.json`

两件事测的东西不同:检查点测**准不准**,事件时间戳测**反应快不快**(确认延迟)。

---

## 第一部分:标检查点帧

### 打开

在 X-AnyLabeling 里打开 `video_testset/checkpoints/` 目录。每张图旁边已有同名 `.json` 预标注,
框和类别都由当前模型预填,**你只做校正**。

### 校正规则(和 Phase 0 标注规范一致)

| 情况 | 怎么做 |
|---|---|
| 框漏了一张牌 | 补一个框,选类别 |
| 框多了(不是牌) | 删掉 |
| 框歪了/框住两张牌 | 调整到贴住单张牌 |
| 类别错了 | 改成正确的 |
| **牌背** | **不标**,当背景忽略 |
| 侧面/严重遮挡/看不清 | 类别标 `unknown` |

**框的边界**:贴住牌的可见边缘。被遮挡超过 70% 的牌仍然要标。画面边缘的半张牌照标。

### 省时间的提示

- 预标注的检测阈值调得很低(0.15),**宁可多框让你删**,删比画快
- 一帧大约 30~60 秒。先过一遍框,再过一遍类别("两遍法")比逐张纠正快
- 每段的检查点是同一局牌的不同时刻,**牌河里的牌大部分没变** —— 校正过一帧后,后面几帧会轻松很多

## 第二部分:记录出现事件时间戳

### 这是干什么的

测"一张新牌出现后,系统多久才确认它"。规格要求 **≤0.5 秒**。
所以需要你给出"这张牌是在第几秒出现的"这个真值。

### 怎么记

1. 用能逐帧步进的播放器打开 `video_testset/clips/clipXX_*.mp4`(PotPlayer:方向键逐帧;VLC:`E` 键)
2. 找到一张牌**刚被放到桌上、第一次完整可见**的那一帧
3. 记下**时间**(精确到 0.1 秒)和**牌名**
4. 每段记 3~5 个,挑清楚的记,不用求全

### 帧号换时间

如果你的播放器显示的是帧号:

```bash
python scripts/frame_time.py --fps 30 --frame 137
```

反过来也行:`--time 4.57` 会给出帧号。片段的 fps 写在 `MANIFEST.json` 里。

### 填进 events_gt.json

`build` 已经生成了模板,把示例那行删掉,按这个格式填:

```json
{
  "clips": {
    "clip01_7415194948674": {
      "events": [
        {"tile": "t3", "t": 4.5,  "note": "对家打出"},
        {"tile": "w9", "t": 12.2, "note": "我摸的牌亮出来"},
        {"tile": "b5", "t": 21.8, "note": ""}
      ]
    }
  }
}
```

- `tile` 用项目标准类名:`w1`~`w9`(万)、`t1`~`t9`(条)、`b1`~`b9`(筒)
- `t` 是**片段内**的秒数(从片段开头算,不是原视频的时间)
- `note` 随便写或留空,只是帮你自己回忆

## 一个已知局限(写在这里免得日后困惑)

评测片段来自抖音视频,而分类器训练时用过这些视频的部分帧(就是你拖图整理的那批 crop)。
所以**检查点里的"分类准确率"会偏乐观**。

这不影响 Phase 4 真正要验收的东西 —— 跟踪质量、闪烁率、确认延迟都是流水线行为,与分类器
见没见过这些牌无关。分类准确率的权威数字是冻结测试集上的 **99.51%**,不看这里的。
