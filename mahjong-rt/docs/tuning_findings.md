# 参数扫描结论(试点版)

**结果:参数层面调不动。500 组配置(200+300)里,没有一组能在三段片段上同时做到
闪烁 <0.05、准确率不降、ID 切换不涨。**

不是没扫到,是这三个目标在参数空间里互相对立。

## 基线逐段表现

| 片段 | 类别准确 | 闪烁 | ID 切换 |
|---|---|---|---|
| clip01 | 93.7% | 0.062 | 24.0% |
| clip02 | 98.8% | 0.050 | 11.0% |
| clip03 | 95.5% | 0.082 | 18.4% |
| **合计** | **95.62%** | **0.1048** | **19.8%** |

## 扫参能做到什么

在"闪烁 <0.05"单一约束下确实能提升(全 3 段):

| 配置 | 类别准确 | 闪烁 | ID 切换 |
|---|---|---|---|
| 基线 | 95.62% | 0.1048 | 19.8% |
| 扫参推荐 | **97.20%** | **0.0491** | 34.8% ⚠️ |
| 推荐 + track_buffer 恢复 30 | 97.37% | 0.0594 | 32.1% |
| 仅降检测阈值到 0.05 | 95.80% | 0.1086 | 24.4% |

准确率 +1.6、闪烁减半,**但 ID 切换从 19.8% 涨到 34.8%**,而且调 `track_buffer` 救不回来
(恢复到 30/45 只降到 32%),说明主因是关联门限而非缓冲长度。

## 为什么无解

降闪烁和降 ID 切换在参数上是对立的:

* 想让牌**不改口** → 滞回调大(反应变慢),或者让 track 断掉重建
  —— 而重建后的 track 从头投票,它的分歧**不计入闪烁统计**,指标好看了,行为更差了
* 想让 track **不断** → 关联门限放松 → 相邻的牌长得几乎一样,松了就接错人,接错就是改口

根因是**信息不足**:密集排列的麻将牌,光靠框的重叠度(IoU)分不清谁是谁。

## 一个被指标掩盖的陷阱

第一轮扫参只约束闪烁率,搜索直接找到了钻空子的解:把 `track_buffer` 从 30 降到 15,
让 track 频繁断裂重建。闪烁率是按"已确认牌的改口次数"算的,**换个新 ID 从头投票就绕过了统计**。

补上 ID 切换约束后同样的配置仍被选中,因为约束是在 tune 段判定的——该配置在 tune 段
ID 切换 20.5%(通过),在 holdout 段 42.0%(远超)。同一配置两半数据差一倍,说明
**3 段片段做 tune/holdout 划分本身不可靠**。

## 下一步:补信息,不是继续调参

Phase 4 规格任务 3 第 4 条早就留了这条路,实现时默认关着:

> 密集场景关联保护:相邻牌框 IoU 高,关联加入**外观约束**开关
> (用分类器倒数第二层 embedding 的余弦距离,默认关,转头剧烈时自动启用)

关联时除了看"框重不重叠",再看"**这张牌的图像内容和上一帧那张像不像**"。两张挨着的牌
即使框重叠,一个是三万一个是九万,embedding 差得远,就不会接错。

成本很低:分类器本来就在跑,取倒数第二层特征几乎零额外开销;录制格式加一个字段,
就能继续用 replay 秒级验证。

## 评测条件的已知局限(下次重做时注意)

* **stride=3,等效 10fps**。帧间运动是真实 30fps 的 3 倍,关联难度被人为放大,
  ID 切换偏高。有 GPU 能跑全帧率时这些数会全面好转。
* **只有 3 段片段**。tune/holdout 一半就是 1 段,过拟合风险高;逐段约束是更合适的
  判据,但样本仍然太少。规格要求 8~12 段。
* **replay 与实时流水线有 0.5 个点的系统偏差**:实时版分类跟踪框(经过平滑),replay
  分类检测框(为了扫参时不必重跑模型)。相对比较有效,绝对值以实时版为准。

## 这轮真正的产出

不是那组参数,是**工具链通了**:

* 一次模型推理(1 小时)录成 1.2 MB,含 891 帧、57,261 个检测框
* 之后每试一个配置 **36 秒**,提速 100 倍
* 片段扩到 8~12 段、能跑全帧率之后,几十分钟就能得到可信结论
