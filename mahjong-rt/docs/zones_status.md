# zones 模块现状与后续方案

**当前状态:默认关闭**(`configs/pipeline.yaml` 里 `zones.enabled: false`)。

主链路(检测 → 跟踪 → 投票 → 状态机)不依赖它,关闭后所有牌统一报 `unknown_zone`,行为不受影响。

## 为什么关掉

试了两版纯启发式,人工目视判断错误率仍然偏高,不足以使用。

**v1**:只看纵向位置 + 相对尺寸。
失败原因:阈值 `hand_bottom_frac=0.72` 卡掉了大部分手牌(实测最大尺寸层的 ny 10 分位是 0.69),107 张牌的画面里只认出 3 张手牌。

**v2**:尺寸聚类 + 共线成组 + 桌心扇区。
修掉了一个真 bug(`_rows` 用"和上一个框比"导致链式漂移,79 张牌被串成一组;改成和条带均值比后,结构组从 2 个变成 6~9 个)。手牌识别改善到 12/8/11 张。但三家归属仍然经常整家判成 0,人工判断错误率高。

## 已经验证为真的东西(下次别重新推导)

基于 120 张标注图、4446 个框的统计:

- **尺寸就是深度,单调可靠**:短边 15.9px → 81.7px 时,纵向位置 ny 从 0.391 → 0.806。所以用尺寸估距离比用像素阈值稳,换机位/分辨率都不失效。
- **横向位置单独无效**:nx 在每个深度层都是均值 ~0.5、标准差 ~0.17,没有左右双峰。"靠左就是上家"这个判据单独用不成立。
- **对手牌河几乎是水平的**:中等深度层拟合斜率 0.031,所以"透视导致倾斜"不是失败原因。

用户确认的场景事实:上下家能看全、对家的牌可能上下堆叠但整体对齐、牌池与对手区域边界清楚。

## 后续方案(按推荐顺序)

**A. 先标一小批区域数据(推荐)**
标 20~30 张图,每张把牌圈成几组标上归属(我的手牌 / 牌池 / 上家 / 对家 / 下家 / 牌墙),约半小时。
有了它,这个模块就能像检测和分类一样**用数字驱动**:调参有据可依,也可以直接训一个很小的分类器(输入:框的尺寸、位置、与邻居的关系;输出:区域),几乎肯定比手调阈值准。

**B. 降级到只做「我的手牌 vs 其他」**
这是唯一价值最高、也最容易做对的区分(知道自己手上有什么牌,才能给出打牌建议)。放弃按玩家细分。

**C. 等 Phase 4 时序能力完善后再做**
桌子是刚体,相机在动。跟踪稳定后可以跨帧累积一个桌面模型,比单帧推断可靠得多。但这依赖跟踪先做扎实。

## 什么时候值得重启

当上层功能真的需要"谁打了什么牌"时(比如做读牌/点炮归属)。
如果只做"记牌 + 提示自己该打什么",`my_hand` + 全局牌池统计就够了,不必按座位细分。
