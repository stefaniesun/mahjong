# 静态图片区域识别 100% 验收设计

## 1. 背景与目标

当前区域判定模块根据原图归一化位置、相对尺寸、最近邻距离和簇内多数投票，将检测到的牌分为：

- `my_hand`
- `seat_left`
- `seat_across`
- `seat_right`
- `river`

现行算法在 20 张人工标注图片、899 个真值框上的图级五折交叉验证准确率为 94.53%，其中 `seat_across` 召回率为 71.0%。主要困难是 `seat_across` 与 `river` 在位置、密度和聚簇结构上重叠。

本设计面向静态图片。不同批次之间允许摄像头位置、旋转、缩放、裁剪和透视明显变化，但每张图片中桌面四角或边框稳定可见。每个新场景允许使用独立校准集，最终测试图片与标签必须隔离。

目标是把以下条件设为工程验收门槛：

1. 当前 20 张图片全部预测正确，即 899/899；
2. 新增隔离测试集全部预测正确，即 N/N；
3. 所有区域召回率均为 100%；
4. 正式验收不允许用 `unknown_zone` 降低错误率。

该目标是发布门槛，不构成对任意未知静态图片的数学保证。若图像信息不足以唯一确定归属，必须通过标注规范和数据准入规则解决。

## 2. 设计原则

1. 区域识别继续作为检测器之外的独立后处理模块。
2. 优先采用可解释的桌面几何、牌面朝向和布局结构，不训练与牌面检测绑定的区域头。
3. 校准集、开发集和最终测试集按图片严格隔离。
4. 禁止根据最终测试标签调整参数。
5. 任一模块失败必须显式报告，禁止静默退回原图固定阈值。
6. 保留现有规则作为基线和兼容回退，但不作为正式方案的默认路径。

## 3. 方案比较

### 3.1 方案 A：透视归一化与固定区域边界

每张图定位桌面四角，将桌面变换到统一鸟瞰坐标，再用校准集拟合五个多边形区域。

优点是实现简单、可解释且适应机位变化。缺点是 `seat_across` 和 `river` 的真实边界不完全由位置决定，边界牌仍会误判。该方案作为几何基础，不单独承担 100% 验收目标。

### 3.2 方案 B：透视归一化与结构化布局

在方案 A 上增加桌边距离、牌框方向、排列方向、同行关系、间距、连续性和碰杠结构，并将整桌牌作为整体求解。

该方案可解决多数逐框规则错误，但面对空间布局相似的对家牌与牌池牌时仍缺少独立信号。

### 3.3 方案 C：几何、朝向、结构和校准联合求解

方案 C 在方案 B 上增加牌面朝向评分、校准分布、全局约束和歧义诊断，是本设计采用的方案。

## 4. 总体数据流

```text
原始静态图片 + 牌框
        ↓
桌面四角/边框定位与质量检查
        ↓
单应变换，映射到统一桌面坐标
        ↓
位置、桌边距离、尺寸、密度、朝向特征
        ↓
牌组和邻接图构建
        ↓
结构化全局区域求解
        ↓
区域标签 + 置信间隔 + 证据 + 失败诊断
```

## 5. 核心模块

### 5.1 `TableNormalizer`

输入原始图片、桌面四角或边框、牌的 `xywh` 框，输出统一桌面坐标中的牌几何。

职责：

1. 将桌角统一排序为左下、左上、右上、右下；
2. 计算原图到标准桌面的单应矩阵；
3. 将桌面映射到固定尺寸坐标系，例如 1000×1000；
4. 映射牌框四角，而不只映射中心点；
5. 计算中心、映射后尺寸、主方向以及到四条桌边的距离；
6. 输出四边拟合残差、单应矩阵条件数和桌面覆盖率等质量指标。

桌面定位采用两级策略：

- 首选自动检测桌面边框并拟合四边交点；
- 自动定位失败时，开发阶段允许使用人工四点诊断；正式自动验收中定位失败直接计错。

禁止在定位失败时静默使用原图 `nx/ny`。

### 5.2 `ZoneCalibrator`

每个场景使用独立校准集拟合区域先验。校准数据包括：

- 图片路径和尺寸；
- 桌面四角；
- 牌框；
- 人工区域标签；
- 可选牌面类别。

校准结果按 `calibration_id` 保存到 `configs/zones/<calibration_id>.json`，内容包括：

- 每个区域的核心多边形；
- 相邻区域边界带；
- 位置与桌边距离分布；
- 典型排列角度、尺寸、间距和密度分布；
- 特征权重和有效范围；
- 配置版本、校准集摘要和拟合参数。

最终测试仅加载校准结果，不读取测试标签。

### 5.3 `TileOrientationEstimator`

对每个牌 crop 分别以 0°、90°、180°、270°输入现有牌面分类器，比较：

- 最大类别概率；
- 不同旋转下类别预测的一致性；
- 方向间得分差；
- crop 图像质量。

输出四方向分数和方向置信间隔，不直接以硬方向单独决定区域。

若现有分类器无法提供稳定方向证据，再训练独立轻量朝向分类器。该模型只判断方向，不与检测器或区域头绑定。

### 5.4 `LayoutGraphBuilder`

在标准桌面坐标中将每张牌作为节点，建立局部邻接边。边特征包括：

- 中心距离和框间空隙；
- 主方向差；
- 尺寸比例；
- 朝向一致性；
- 是否构成连续行列；
- 是否出现三张或四张同类牌。

输出玩家横排、侧边纵排或斜排、碰杠组、牌池散乱组和孤立牌候选。

不得使用无约束单链聚类，因为它会通过中间牌将 `seat_across` 与 `river` 串成一个簇。应使用带方向、间距和最大跨度限制的图分组方法。

### 5.5 `StructuredZoneSolver`

每张牌对每个区域计算单牌代价：

\[
C_i(z)=w_pC_{position}+w_oC_{orientation}+w_eC_{edge}+w_sC_{size}+w_dC_{density}
\]

全局目标再加入成组一致性和布局约束：

- 稳定牌组倾向属于同一区域；
- 玩家牌组排列方向应与对应桌边一致；
- `river` 允许散乱、多方向和多簇；
- 玩家区域不能无约束跨越桌心；
- 紧密碰杠组不应被拆分；
- 对家组与顶边的关系应强于与桌心的关系。

可先采用穷举候选组标签或动态规划；仅当问题规模需要时再引入图优化或整数规划。求解器输出：

- 最终 `zone`；
- 最佳与次佳代价；
- 置信间隔 `margin`；
- 主要证据；
- 是否位于歧义边界；
- 失败原因。

## 6. 接口与兼容性

保留现有 `assign_zones(...)` 入口，新增可选上下文：

- 桌面几何；
- 校准配置；
- 图片 crop 或朝向分数；
- 调试输出开关。

`analyze_layout(...)` 返回结构化调试信息。旧版固定阈值规则保留为基线，在缺少新配置时可显式启用，但正式验收必须使用方案 C。

## 7. 标注规范和数据准入

区域真值必须由静态图片中的可见证据唯一确定。统一规则如下：

1. 摆在某玩家面前的牌，包括定缺牌和碰杠牌，归该玩家；
2. 中间散乱弃牌归 `river`；
3. 边界牌以牌框映射后与区域核心/边界多边形的关系和明确布局结构共同判定，不能只凭标注者直觉；
4. 剩余错误样本由两名标注者独立复标；
5. 若两名标注者在不参考历史标签时无法一致判断，则该样本不具备可识别真值，必须修订规则或排除出任务定义；
6. 洗牌和牌局结束等区域概念不存在的画面不得进入数据集。

## 8. 数据隔离与验收协议

每个新场景拆分为：

- 校准集：允许用于拟合场景参数；
- 开发集：允许查看错误并修改通用算法；
- 最终测试集：标签封存，版本冻结后运行。

所有划分必须按图片进行。同一图片中的框不得跨集合。最终测试失败后，该测试集转为开发数据；修复后必须建立新的未见测试集，原测试集不能继续作为盲测证明。

每次报告两个指标：

\[
accuracy=正确输出数/全部GT框数
\]

\[
coverage=非unknown输出数/全部GT框数
\]

正式合格条件：

- 当前数据 899/899；
- 新增隔离测试集 N/N；
- 准确率和覆盖率均为 100%；
- 五个区域召回率均为 100%；
- 桌面定位失败、漏输出、重复输出均计错；
- 不允许以 `unknown_zone` 通过正式验收。

建议每个新机位批次至少使用 20–30 张校准图、20 张开发图和 30–50 张封存测试图，并连续三个新机位批次全部通过。

## 9. 测试设计

### 9.1 单元测试

覆盖：

- 桌角排序；
- 单应矩阵和逆变换；
- 桌边距离；
- 牌框四角与方向映射；
- 退化四边形；
- 朝向评分；
- 布局图构建；
- 牌组拆分和合并；
- 全局约束；
- 校准配置序列化和版本校验；
- 明确的失败输出。

### 9.2 合成几何测试

对标注图片施加合理范围的平移、缩放、旋转、透视、裁剪和分辨率变化。变换前后区域结果必须完全一致。该测试验证几何归一化，不替代真实机位测试。

### 9.3 当前数据回归

将现有 `accuracy >= 0.92` 提升为逐框全等。失败信息必须包含：

- 图片名和框序号；
- GT 与预测；
- 最佳和次佳代价；
- 置信间隔；
- 特征值与主要证据；
- 所属错误类别。

同时输出混淆矩阵、五区召回和 `seat_across` 错误数。

### 9.4 新场景隔离测试

测试集应覆盖不同牌局阶段、光照、遮挡、牌面摆放和透视角度。只允许使用校准结果和冻结算法。任何错误均判该版本不合格。

## 10. 失败分类与闭环

每个错误必须归类为：

1. 桌角定位错误；
2. 透视映射错误；
3. 标注规则歧义；
4. `seat_across` 与 `river` 位置重叠；
5. 朝向证据错误；
6. 牌组构建错误；
7. 全局求解约束错误；
8. 输入框不完整或错误。

只修改对应模块，避免继续对全部数据做无约束阈值网格搜索。

## 11. 实施顺序与消融实验

1. 增加桌角数据格式和 `TableNormalizer`；
2. 在标准桌面坐标中重建当前规则并重新评测；
3. 增加校准器和区域先验；
4. 增加带方向与跨度约束的牌组结构；
5. 验证现有分类器的四旋转朝向信号；
6. 增加结构化全局求解器；
7. 对剩余错误执行双人复标和失败分类；
8. 冻结版本并运行全新隔离测试集。

每一步报告：当前数据正确数、图级交叉验证准确率、五区召回、`seat_across` 错误数和新增隔离测试正确数。

## 12. 非目标

本次不处理：

- 视频跟踪和跨帧投票；
- 出牌顺序或轮转推断；
- 修改牌面检测模型；
- 将区域分类头塞入检测器；
- 通过记忆最终测试标签获得 100%。
