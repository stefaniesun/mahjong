# 牌背标注指引

24 张图,只标一个类 `tile_back`。**没有类别判断,纯画框**,估计 30~40 分钟。

## 为什么要标

引擎侧的 `VisionSnapshot` 需要 `wall_count`(牌墙剩余张数)——这是打牌模型判断"还剩几轮"的关键输入。
另外暗杠反扣的牌也要靠它识别。

## 为什么单独标、单独训

牌背和牌面**不能混在一个标注集里分批标**:如果 A 图标了牌背、B 图没标,对模型就是矛盾信号
(同一个东西这里说是目标、那里说是背景),会训得很不稳定。

所以做法是**训一个独立的牌背检测器**,和现有牌面检测器并行跑:

- 牌面检测器:牌背当背景 ✅(现在就是这么训的,一行不用改,98.4% 基线继续有效)
- 牌背检测器:牌面当背景 ✅(只标牌背,内部一致)

推理开销约 +1~2%(牌背模型小、跑低分辨率、而且几秒跑一次就够——牌墙数量变化很慢)。

## 怎么标

1. X-AnyLabeling 打开 `output/back_annotation/images/`
2. 类别文件用同目录的 `classes.txt`(只有 `tile_back` 一个)
3. **所有看得见的反扣牌/立牌都标**,包括:
   - 牌墙(贴着桌边那一长条)
   - 对家、上家、下家的立牌
   - 暗杠反扣的牌(如果画面里有)
4. 每张图大约 30~50 个框

### 不要在标注时区分"这是牌墙"还是"这是谁的手牌"

只有一个类 `tile_back`。牌墙在哪、手牌在哪**随桌子和机位变**,而"这是一张反扣的牌"是稳定的。
把位置判断塞进模型,换个机位就得重训 —— 和区域判定不进模型是同一个理由。
牌墙与手牌的区分放在后处理:牌墙贴桌边、排成整齐长条,几何上分得开。

### 堆叠的牌:看得见几张就标几张

目的是**数数**,所以不能只标最上面那张 —— 那样数出来直接少一半。

| 情况 | 怎么标 |
|---|---|
| 能看见两层 | 上下**各画一个框** |
| 只看得见上层,下层完全被挡 | **只标上层**,下层不要凭猜补 |
| 被手挡住一半 | **标**,画可见部分 |
| 完全看不见 | **不标** |

原则:**看见几张标几张,看不见的不要补**。少标一层可以在后处理里乘 2 修正;
凭猜画的框会污染训练。

**这批图基本不涉及这个问题** —— 放大核对过,这些视频用的是自动麻将桌,
牌墙是**单层**一排立牌(牌与牌之间的竖缝清晰可数),不是传统的双层码放。

## 关键规则

| 情况 | 怎么标 |
|---|---|
| 牌墙**双层堆叠** | **上下各标一个框**,别把两层框成一个 |
| 只露出一条边的牌 | 标(能看出是一张牌就标) |
| 被手/牌面完全挡住 | 不标 |
| 牌面(有花色的) | **不标**,这个包只要牌背 |
| 实在分不清是牌还是别的 | 不标,宁缺勿错 |

## 省时技巧

牌背排列规整、大小相近,别一个个画:

- 画好第一个框后,**复制粘贴**再拖到下一个位置(X-AnyLabeling 支持 Ctrl+C / Ctrl+V)
- 一排牌墙尺寸几乎一样,复制拖动比重画快好几倍
- 先标大片规整的牌墙,再补零散的立牌

## 不用追求完美

这个模型只要能"数出牌墙还有几张、认出有反扣牌",不需要像牌面那样 99%。
漏标几个边缘模糊的没关系,**别为了完美拖慢速度**。
