# 怎么填 events_gt.json

给评测用的事件真值。有了它才能验证"谁打了什么牌"这类事件识别得对不对 ——
没有它,做出来只能靠肉眼看,这个项目在区域判定上已经栽过一次(报过 92.5%,实际 88.9%)。

**工作量**:一段 30 秒大约 10~15 条,三段合计约 30 分钟。**先填一段就能开工**。

---

## 1. 打开哪个视频

片段在 `output/video_testset_pilot/clips_full/`:

| 文件 | 时长 |
|---|---|
| `clip01_7507945925261200.mp4` | 30 秒 |
| `clip02_7499348207492304.mp4` | 30 秒 |
| `clip03_7504292741762927.mp4` | 30 秒 |

用 PotPlayer / VLC / MPC 打开(**Chrome 放不了**,这些片段是 mp4v 编码的)。

**时间从片段开头算起,不是原视频的时间。** 片段第 1 秒就写 `1.0`。

### 时间可以不填

`t` 是**可选**的。不填也能验证"事件序列对不对"——谁打了什么、谁碰了谁,这才是核心问题。
不填只会丢一个指标:**确认延迟**(牌出现到系统确认的秒数),而那个本来就一直没测过。

没有时间时,事件按**列表里的先后顺序**跟系统输出做序列对齐。对齐靠每条自带的
`谁+做了什么+什么牌` 三个信息约束,一般不会错;只有连着漏掉好几条时才可能漂。

**折中办法:每 5 条左右给一个大概时间当锚点。** 漂了能拉回来,又几乎不增加工作量。

---

## 2. 一条事件长什么样

```jsonc
{
  "t": 3.2,             // 秒，从片段开头算起。看到动作完成的那一刻，±0.3 秒就够
  "who": "left",        // 谁做的: me / left / across / right
  "type": "discard",    // 什么事: discard / pong / kong / hu / dingque
  "tile": "t5",         // 什么牌: w=万 t=条 b=筒，w1~w9 / t1~t9 / b1~b9
  "from": null,         // 碰/杠/胡 才填：这张牌是从谁那儿来的。打牌填 null
  "note": ""            // 看不清、不确定就写在这儿
}
```

### `who` 怎么定

以**戴眼镜的人(画面最下方那排手牌)** 为基准:

```
            对家 across
   上家 left          下家 right
            我 me  (画面下方)
```

麻将逆时针轮转:**我打完 → 下家 right → 对家 across → 上家 left → 回到我**。

### `type` 各是什么

| 值 | 中文 | 什么时候记 |
|---|---|---|
| `discard` | 打牌 | 一张牌被扔进中间牌池的那一刻 |
| `pong` | 碰 | 三张一样的牌被摆到某家面前 |
| `kong` | 杠 | 四张 |
| `hu` | 胡 | 有人推倒亮牌 |
| `dingque` | 定缺 | 定缺牌被摆出来(**这个最后再说,可以先不填**) |

**摸牌不用记** —— 摸进别人手里的牌本来就看不见,决策引擎也不需要。

### `tile` 编码

`w` = **万**,`t` = **条**,`b` = **筒**。注意 **t 是条不是筒**。

`w1` = 一万,`t9` = 九条,`b5` = 五筒。

四川麻将没有字牌花牌,所以只有这 27 种。

---

## 3. 填的时候

**只填看得清的。** 看不清就跳过,或者填上 `"tile": null` 加个 note 说明 ——
**漏记比记错好**。记错会让评测把对的判成错的,那比少几条样本糟糕得多。

**顺序按时间排。** 不用严格,但排好了自己也容易检查。

**碰牌记 `from`。** 碰是唯一能直接看出"是哪一家"的动作,它是整条轮次链的锚点,
所以这几条格外值钱。谁打出的那张被碰走了,就填谁。

---

## 4. 完整示例

```jsonc
{
 "format": "mahjong_events_gt/1",
 "clips": {
  "clip02_7499348207492304": {
   "video": "clips_full/clip02_7499348207492304.mp4",
   "source_start": 165.0,          // 这段在原视频里的起点，仅供追溯，别改
   "events": [
    {"t": 2.4,  "who": "me",     "type": "discard", "tile": "b7", "from": null, "note": ""},
    {"t": 5.1,  "who": "right",  "type": "discard", "tile": "t3", "from": null, "note": ""},
    {"t": 7.9,  "who": "across", "type": "pong",    "tile": "t3", "from": "right", "note": ""},
    {"t": 9.6,  "who": "across", "type": "discard", "tile": "w9", "from": null, "note": ""},
    {"t": 13.0, "who": "left",   "type": "discard", "tile": null, "from": null, "note": "手挡住了没看清"}
   ]
  }
 }
}
```

注意第 3、4 条:对家碰了下家打的三条之后,**轮次跳到对家**,由对家继续打牌 ——
碰是唯一会打乱逆时针顺序的动作,这正是它做锚点的原因。

---

## 5. 填完之后

存回 `output/video_testset_pilot/events_gt.json`,然后跑一下自检:

```bash
python mahjong-rt/scripts/check_events_gt.py
```

它会检查:牌名合法、时间在 0~30 秒内、`who` 拼写对、轮转顺序有没有明显矛盾
(比如同一家连打两张中间没有别人)、同一张牌是不是出现超过 4 次。
**有问题它会指出来,不会改你的文件。**
